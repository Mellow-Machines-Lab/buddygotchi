Boop's architecture

How Boop's pieces fit together, and what each one sends to the next. The code is the detail: each piece below names where it lives, and the packages' own ARCHITECTURE.md files explain them.

Updated 2026-10-11.

The shape Where the pieces join

The shape

Boop is a Mac app plus a small screen on your desk. Data flows one way: from your coding agents (Claude Code, Codex), through the Mac app, to the device. Boop only watches and reports. It never approves or blocks anything an agent does. Three packages handle the general parts (reading agent hooks, asking the multiple-choice model, talking to the device), and they know nothing about Boop or each other. Boop's own code connects them.

Below, one Claude Code turn finishes and we follow it through. Each row shows a piece on the left and what it sends next on the right. The examples come from a real run, cut short where you see ….

  5. View: sentences for Jev

    TranscriptView writes the event as a sentence Jev can read, using earlier events for context, such as when the turn started and how many tools it used. A finished turn is worth asking Jev about.

  7. MellowHarness + Jev package

    Builds the prompt: Boop's personality and rules (the steering files), then recent history, then the new event. It asks all of Boop's questions in one request to Jev, the multiple-choice model. Every question is multiple choice, and each option says when it applies and when it doesn't.

    Two of the questions (options trimmed), and the answers 
    After NOW, what is Boop's mood?
  calm      Stay calm: NOW is no reason MOOD gives to leave it…
  happy     Good spirits: work is going well, or a win just came…
  excited   Thrilled: a very long turn finished done…
            not for: a shorter turn finishing…
  …
react.mood: none | happy | excited | proud | curious | …

mood calm · react.mood excited · react.animation success
react.loops once · say.feeling none · say.about start · say.kind word

LinkKit (linkkit/)
  1. LinkKit

    Carries the messages over Bluetooth or USB. On the board it plays one request at a time: a next request waits for the current one to finish, up to its ttl (5 s here), then plays.

    ended back to the Mac, once per do 
    {
  "t": "ev",
  "kind": "ended",
  "data": { "id": 558386703, "how": "done" }
}
    Boop marks the reaction finished, and the next prompt tells Jev what Boop did.
state and do down · ended and taps back up
  1. The device (firmware/)

    Draws the face and plays the clip. There are two boards: the CYD, with a pixel-art face, and the AMOLED, with a soft gel face. A tap reacts on the board at once, then is reported to the Mac.

    A tap, going back to the Mac 
    {
  "t": "ev",
  "kind": "tap",
  "did": "poked"
}
    Boop records it as a poke, which also prompts Jev.

Three speeds

LoopRuns onHandlesNever waits for
Reflex (instant)The deviceReacting to taps, blinking, the alert when an agent needs you, the order requests play inThe Mac
Reactive (fast)The Mac's rulesA hook changing the screen, or a short animation a rule playsJev
Deliberative (slow)MellowHarness and JevEvery mood change and reaction, including to a finished turnNothing, and nothing waits for it

Each loop's time budget is in internal/VERIFICATION.md §8.

Where the pieces join

Each package has its own vocabulary: agent-hooks has AgentEvents, MellowHarness has Events and lines, LinkKit has state, do and ev. Boop translates between them in the places below. Everything sent to the device goes out through Runtime.

From → toWhereWhat happens
agent-hooks → BoopAdapter.event(from:), Runtime.hookEach hook line becomes an AgentEvent, kept as a MellowHarness Event with its facts in data
agent-hooks → the rulesCoreagent-hooks' SessionTracker tracks each session and whether an agent needs you. The core adds what the screen shows, what takes priority, and the rules' short animations
Boop → MellowHarnessPipelineEach event is logged and run through the core's rules in one step. TranscriptView defines the sentence for each kind of event, and Runtime registers the two outputs, mood and react
Boop → LinkKit (what the screen shows)Runtimelink.update(state:) on every change, on connect, in answer to hello and every 10 s
Boop → LinkKit (a rule's short animation)Runtime.playRuleplay: if_free: sent at once, skipped while one of Jev's reactions is playing
Jev → LinkKit (reactions)ReactAction → Runtime.queueplay: next with a 5 s ttl. The reaction stays in progress until the device's ended, which Reactions reads
Boop → which deviceDeviceChooserThe board over Bluetooth, or, while one runs on this Mac and Settings is told to use it, the simulator (simulator/: the firmware's own code in a web page) over its USB socket. Nothing above the transport knows which
A demo → BoopRuntime.playA character pack's script (demo/demo.jsonl) comes in through the same doors as real work: a hook as a hook, a tap as the device's, talk as the mic's; its answers are forced passes. DemoRecorder keeps what the device was sent, for the simulator's page to play back
LinkKit → BoopRuntime.device, Runtime.deviceEventA tap becomes a poke through the pipeline; talk_on and talk_off drive push-to-talk
